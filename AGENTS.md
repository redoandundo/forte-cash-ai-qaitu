# AGENTS.md — правила репозитория Qaitu

## Назначение

Этот репозиторий принадлежит команде Qaitu, участвующей в Datathon26 с кейсом ForteBank. Цель — полностью локальная система анализа видео кассовой зоны с таймкодом, объяснимым результатом и JPEG-доказательствами.

## Обязательное чтение перед работой

1. `GOALS.md`.
2. Актуальная фаза в `PLANS.md`.
3. `knowledge/TEAM_CONTEXT.md`.
4. `knowledge/PROJECT_CONTEXT.md`.
5. `knowledge/current_state.yaml`.
6. Контракт и handoff, относящиеся к текущей задаче.
7. Соответствующее руководство в `docs/team/`.

Не полагайся только на историю чата. Репозиторий является источником устойчивого командного контекста.

## Роли и ownership

- Тимлид: `src/api/**`, `src/jobs/**`, `src/core/**`, `.github/**`, общая архитектура и integration tests.
- ML-инженер: `src/ml/**`, `configs/ml/**`, `tests/ml/**`, `reports/ml/**`, ML handoff.
- Inference-инженер: `src/inference/**`, `configs/inference/**`, `tests/inference/**`, `reports/inference/**`, inference handoff.
- Изменения `docs/contracts/**`, `AGENTS.md`, `GOALS.md`, `PLANS.md` и `knowledge/current_state.yaml` принимает тимлид.

Изменение чужой зоны должно быть минимальным, выделенным отдельным commit и явно описанным в PR.

## Code discovery

Для исходного кода предпочитай `codebase-memory-mcp`:

1. `search_graph`;
2. `trace_path`;
3. `get_code_snippet`;
4. `query_graph`;
5. `get_architecture`.

Перед поиском проиндексируй текущую ветку, если индекс отсутствует или устарел. Для строк, конфигурации и не-кодовых файлов разрешены `rg` и обычное чтение файлов. Кэш графа не коммитится.

## Безопасность данных

- Не отправляй видео, кадры, модель или внутренние документы во внешние AI API.
- Не коммить raw video, dataset labels, dataset-derived detailed reviews, generated clips, storyboards, evidence, веса, исходный PDF кейса, secrets, `.env`, `.venv` или локальные кэши.
- Не включай абсолютные пользовательские пути в код, manifests или публичные отчёты.
- Не утверждай юридическое нарушение: используй формулировку «признаки возможного нарушения».
- Не маскируй техническую ошибку как `no_violation`.
- Репозиторий публичный. Перед добавлением материалов проверь, разрешена ли их публикация условиями Datathon26.

## Git

- Не коммить напрямую в `main`, `develop` или `integration/ml-inference`.
- Работай только в назначенной `feature/*` ветке.
- Не используй `git add .`; добавляй явные пути.
- Не используй force push, `reset --hard` или удаление чужих изменений.
- Перед commit запускай `git diff --check` и относящиеся к изменению тесты.
- Не меняй `git user.name` и `git user.email` без решения человека.
- Push, PR и merge должны соответствовать `docs/team/GITHUB_TEAM_ARCHITECTURE.md`.

## Контракты и handoff

- Общение компонентов происходит через файлы в `docs/contracts/`.
- Участник обновляет только свой handoff в `docs/handoffs/`.
- Handoff обязан содержать commit SHA, команды воспроизведения, фактические тесты, ограничения и следующий шаг.
- ML artifact без manifest, preprocessing и checksum не считается готовым.
- Breaking change контракта требует отдельного описания и согласования тимлида.
- Публичный API обязан точно соответствовать `docs/contracts/api_contract.md`, даже если внутренние dataclasses используют другие названия.

## Качество

- Сначала корректность и воспроизводимость, затем оптимизация.
- Новая логика сопровождается focused tests.
- В отчёте указываются только реально выполненные команды и наблюдаемые результаты.
- Не объявляй тест пройденным, если он не запускался.
- Не расширяй scope следующей фазой без необходимости.

## Контекст после работы

После значимой фазы обнови принадлежащий роли handoff. Тимлид после интеграции обновляет `knowledge/current_state.yaml`. Не дублируй один факт во многих файлах: ссылайся на его основной источник.
