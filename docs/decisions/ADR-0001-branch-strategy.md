# ADR-0001: Стратегия веток

Статус: accepted

Дата: 2026-10-17

## Контекст

ML и inference должны развиваться параллельно. Если inference станет дочерней веткой незавершённого ML-кода, работа второго участника будет зависеть от нестабильной истории первого.

## Решение

Использовать:

- `main` для стабильной demo/release-версии;
- `develop` для проверенной общей разработки;
- отдельные `feature/*` ветки каждого владельца;
- временную `integration/ml-inference` для соединения двух компонентов.

Feature-ветки создаются от `develop`. Integration принимает Draft PR, затем после end-to-end проверки вливается в `develop`.

## Последствия

- Участники работают независимо через contracts.
- Интеграционные проблемы обнаруживаются до `develop`.
- Требуются handoff и дисциплина ownership.
- Нельзя переписывать опубликованную общую integration-ветку.
