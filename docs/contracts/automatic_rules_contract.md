# Автоматическое сопоставление правил, v1

Владелец: тимлид. Каталог: `src/fortebank_audit/rules.py`, три проверенных правила
CASH-02/03/04, пункты 20 и 22 постановления НБРК № 231. Остальные нормы из
legal/README.md остаются исследовательским списком и автоматически не применяются.

## Подключение без изменения inference участника

При startup режима qwen API оборачивает полученный verifier в `RuleAwareVerifier`.
Его интерфейс остаётся `verify(context)` и `.backend`. Сначала выполняется
обычная проверка участника. Только для possible_violation/high без limitations,
с полным контекстом before/start/peak/end/after, тот же локальный backend получает
дополнительный запрос оценки наблюдаемых условий по тем же JPEG. Вторая модель,
внешний API и новые веса для слоя правил не требуются.

Внутренний `as_dict()` дополняется `rule_assessment`; базовый JSON-формат Qwen
участника не меняется. RuleAwareVerifier сохраняет все исходные поля и добавляет
в измерения время генерации и максимальную VRAM дополнительного запроса.

## Условия и доказательства

Модель возвращает один объект `facts` + `limitations`. Facts содержат ровно один
элемент на каждый уникальный id из каталога (восемь условий):

```json
{
  "fact_id": "cashier_leaves_workplace",
  "status": "supported",
  "confidence": "high",
  "evidence": [
    {"frame_role": "start", "timestamp_sec": 10.0},
    {"frame_role": "end", "timestamp_sec": 20.0}
  ],
  "explanation": "Синтетический пример описания видимого перемещения между кадрами"
}
```

Допустимые status: supported/contradicted/unknown; confidence: high/medium/low.
Supported и contradicted требуют непустых ссылок на кадры. Пары role/timestamp
должны точно совпасть с реально переданным контекстом. Неизвестные/дублирующиеся
условия, выдуманные кадры, NaN и нарушение schema отклоняются. Версия модели,
checksum, границы эпизода и список переданных кадров добавляются нашим кодом,
а не генерируются моделью. Assessment другого эпизода/модели не принимается.

Full context требует пяти разных временных отметок в правильном порядке, с
кадрами строго до и после интервала. Для автоматического совпадения:

- все условия конкретного правила supported/high;
- у full_context_visible указаны все пять ролей;
- отсутствие клиента во время действия подкреплено start/peak/end;
- уход кассира подкреплён start/end;
- завершение предыдущего обслуживания подкреплено before/start;
- действия, отслеживание денег и незавершённое обслуживание имеют как минимум
  два разных кадра; положение ранее принятых денег вне хранилища — минимум один;
- нет material limitations ни основного verifier, ни проверки условий.

Ни category, ни confidence сами по себе не выбирают правило. Unknown или
contradicted у любого обязательного условия блокирует именно это правило.
Несколько полностью поддержанных правил сохраняются вместе.

## Результат и ручная коррекция

Детерминированный код выбирает label/document/section/URL из локального каталога.
`status=matched` означает автоматическое сопоставление наблюдений с нормативной
гипотезой, а не доказанный факт нарушения. Applicability явно сообщает способ
сопоставления, условия, таймкоды, ограничения и необходимость проверки человеком.

Внутренний AnalysisDetail содержит `rules[]`; `rule` сохраняет первое правило для
совместимости. Публичная схема API не расширяется: тип события конкретизируется,
в description добавляются все основания и источники. Verdict, число эпизодов и
JPEG не изменяются. Ручной override показывается отдельно; отмена ручного выбора
восстанавливает исходные автоматические правила и описание.

## Ошибки, стоимость и пределы

Один дополнительный запрос на подходящий эпизод, max_new_tokens=2048, максимум
один повтор при schema/reference error. CUDA/backend failure не повторяется.
Неисправимый ответ приводит к failed/null/[], не к no_violation и не к скрытому
пропуску проверки правил. Для normal_activity/insufficient_evidence, medium/low,
неполного контекста или limitations дополнительного вызова нет.

JSON-валидация доказывает согласованность ссылок, но не истинность визуальных
утверждений модели. Несколько кадров не гарантируют непрерывную видимость всего
интервала. Prompt требует unknown при подобных пробелах; качество такого отказа
проверяется на реальных видео. Личность, намерения, полномочия, банковские проводки
и принадлежность денег не выводятся из внешности/одного кадра.

Этот код протестирован синтетически; качество условий и лимит 300 секунд с
дополнительными запросами должны быть проверены на улучшенном snapshot до
публичного включения. Полное покрытие нормативной базы и максимальные баллы
из наличия автоматического слоя не следуют.
