# Требования кейса ForteBank на Datathon26

Это безопасная текстовая выжимка для командной работы. Исходный PDF хранится локально и не публикуется в репозитории.

## Бизнес-задача

Создать готовый AI-сервис для анализа видеозаписей работы кассира. Пользователь загружает новое видео и получает verdict, типы событий, таймкоды, описание, evidence и нормативное обоснование.

Результат является подсказкой человеку, а не окончательным юридическим или дисциплинарным заключением.

## Обязательный пользовательский сценарий

1. Пользователь открывает веб-интерфейс.
2. Загружает `.mov`.
3. Видит статус обработки.
4. Получает `Нарушение не обнаружено` или `Обнаружены признаки возможных нарушений`.
5. Для каждого события видит тип, таймкод и описание.
6. Видит 1–3 кадра-доказательства.
7. Видит наблюдаемое действие и соответствующее правило/нормативный источник.

Frontend и серверная часть обязательны. Пользователь не должен вручную запускать код.

## API жюри

- `POST /api/v1/analyze`: multipart-поле `file`, ответ с `job_id`.
- `GET /api/v1/jobs/{job_id}`: `processing`, `done` или `failed`.
- Заголовок: `X-API-Key`.
- Verdict: `violation` или `no_violation`.
- `violations`: список событий.
- Evidence: 1–3 JPEG в base64.
- Максимальное время результата: 5 минут.

Точная схема находится в `docs/contracts/api_contract.md`.

## Локальность и переносимость

- Все модели выполняются внутри сервиса команды.
- При обработке запрещены облачные LLM, multimodal API и внешние recognition services.
- Нельзя передавать наружу видео, кадры или их описания.
- После загрузки весов обработка не должна требовать интернета.
- Используются ресурсы команды; организатор не предоставляет GPU или cloud credits.

## Данные

- Минимум 40 постановочных `.mov` примерно от 10 до 145 секунд.
- FPS от 29, звука нет, размер до примерно 29 МБ.
- Одна камера, одна касса, ракурс сверху.
- Есть бинарная метка и таймкод; тип события не указан.
- Финальный набор включает похожие видео и видео под другим углом.
- На финальной проверке 5 или более видео.
- Тестовые видео нельзя использовать для обучения или передавать третьим лицам.
- Датасет используется только в рамках Datathon26.

## Запреты и non-goals

- Нельзя использовать платные или закрытые AI API.
- Нельзя использовать готовое решение целиком.
- Нельзя распознавать или идентифицировать лица.
- Нельзя использовать звук.
- Не требуются пользовательская авторизация, история, экспорт отчёта или batch upload.
- Нельзя утверждать факты, зависящие от невидимых банковских систем или внутренних журналов.

## Нормативная база

- Юрисдикция: Республика Казахстан.
- Основные источники: НБРК и `adilet.zan.kz`.
- Команда связывает источник, наблюдаемое действие и предполагаемый тип события.
- Выдуманные ссылки и неподтверждённые юридические утверждения снижают оценку.
- По FAQ в датасете нет нарушений, основанных только на закрытых внутренних правилах ForteBank.

## Критерии оценки

| Критерий | Баллы |
|---|---:|
| Качество обнаружения | 25 |
| Локализация и evidence | 15 |
| Классификация события | 15 |
| Обоснованность правил | 15 |
| Устойчивость | 10 |
| Готовность продукта | 10 |
| Техническое решение | 10 |
| Итого | 100 |

Ложных срабатываний должно быть как можно меньше; пропуск нарушения недопустим. Оценка выполняется автоматически по JSON-схеме.

## Что представить

- Публичный URL frontend.
- Публичный URL API и API-ключ для жюри.
- Инструкцию запуска и использования.
- Архитектуру и используемые модели.
- Нормативные источники и принцип сопоставления.
- Поддерживаемые типы событий.
- Ограничения и известные ошибки.

## Организационные условия

- Дедлайн: 12:00 согласно ТЗ мероприятия.
- Питчинг для shortlist: 5 минут выступления и 2 минуты вопросов.
- ForteBank оставляет за собой право использовать решение в коммерческих целях.
- Open-source код и pretrained модели допустимы только с лицензией, разрешающей коммерческое использование.
