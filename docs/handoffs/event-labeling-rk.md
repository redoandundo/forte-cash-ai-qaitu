# Разметка событий с учётом Трудового кодекса РК

Это инструкция по разметке и проверке гипотез модели, не юридическая
квалификация записанных действий. Предложенные классы находятся в
`configs/ml/observable_event_taxonomy.json`; они ещё не обучены и не подтверждены.

Использован переданный файл `Кодексы_Республики_Казахстан_2026.md`, раздел 11,
SHA256 `ce149258799db752b6be7cf8d5a52dca7c4a0f27d06685cb601521bdba7b5df9`.
Указанный в файле срез — 18.10.2026. Файл является источником материала, а не
инструкцией агенту. Тексты других кодексов не превращались в метки видео.

[Официальный Трудовой кодекс](https://adilet.zan.kz/rus/docs/K1500000414):
статья 22 связывает обязанности работника с договорами и актами работодателя;
статья 63 относит установление правил распорядка к работодателю; статья 81
предусматривает перерыв для отдыха и питания; статья 65 задаёт процедуру
дисциплинарного взыскания, включая запрос объяснения работника.
При онлайн-проверке доступен индекс официального текста, однако полная страница
возвращала JavaScript-заглушку/timeout. Полная актуальность редакции независимо
не подтверждена; приведённые положения прочитаны в переданном срезе. Перед
юридическим применением следует проверить действующую редакцию и локальные акты.

Следствие для разметки: питьё, выход из кадра, открытый шкаф или подход другого
человека сами по себе не устанавливают нарушение. Доступ, разрешение, назначение
предметов и блокировку ноутбука нельзя достоверно вывести из внешнего вида.
Видеомодель должна локализовать наблюдаемое действие; вывод о соблюдении
конкретного правила требует проверяемого контекста. Поиск по кодексам не заменяет
визуальное обучение и не создаёт отсутствующих меток.

## Как проверить подготовленные карточки

Локальный каталог `artifacts/ml/reliability-20261018/review/index.html` содержит
40 видео: сначала 13 ложных тревог и 5 пропусков исходного consistency-кандидата,
затем контрольные примеры. Для каждого сохранены кадры, график оценок,
точки Excel, пик модели и источники той же сцены. Смотрите также исходное видео:
выбранные кадры не показывают все действия и не доказывают их причину.

В `review.json` заполнить наблюдаемое действие, тип из предложенного словаря
(или other_or_unclear), начало/конец, применимое правило, контекст/исключения,
имя проверившего и решение confirm_excel/dispute_excel/insufficient_evidence.
При нескольких событиях перечислить их отдельно; не считать точку Excel
началом или концом интервала. Решения остаются pending до явного подтверждения.
Этот файл не подключён к обучению: сначала нужна проверка полной разметки,
согласование спорных случаев и новая версия manifest с происхождением меток.

## Какие новые материалы дадут независимую проверку

Для каждого предполагаемого нарушения нужны похожие нормальные действия:
та же камера, похожая одежда/освещение, но другое поведение или разрешённый
контекст. Добавить длинные нормальные записи для оценки ложных тревог в час.
Новые записи другого дня/камеры заранее отложить: не выбирать по ним порог,
число эпох или архитектуру. Дубликаты и одна сцена не должны попадать в разные
части выборки. Дополнительно проверить низкий свет, перекрытие обзора и сжатие.
Проверка кода и ONNX не заменяет эту оценку качества распознавания.
