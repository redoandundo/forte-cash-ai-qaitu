# Проверка понимания видео: spatial-temporal MIL

2026-10-18. Код: `297a5db` (модель и обучение), `14cd4e9` (ONNX),
`02f15d6` (повторное использование замороженных признаков при оценке).
Исходная локальная версия: `a683845`. Все изменения и данные оставлены локально.

## Результат

Новый кандидат улучшил часть метрик на тех же 40 уникальных видео, но не прошёл
критерии замены основной модели. Сохраняется `baseline-audited-v4-development`.
Ни baseline, ни эксперимент не объявляются готовым production-распознавателем.

| Precision | 0.500 | 0.538 |
| Recall | 0.619 | 0.667 |
| Positive F1 | 0.553 | 0.596 |
| Macro F1 | 0.458 | 0.510 |
| Ложноположительные видео / мин отрицательного материала | 1.033 | 0.953 |

| Recall событий в пределах 5 s | 0.364 | 0.455 |
| Средняя ошибка времени, s | 7.133 | 4.474 |

Матрица ошибок кандидата `[TN, FP; FN, TP]`: `[7, 12; 7, 14]`.
Из 21 положительного видео найдены 14, пропущены 7. Из 19 отрицательных
12 вызвали ложную тревогу. По отдельным folds macro F1 составляет
0.444, 0.571, 0.667, 0.300, 0.333 — устойчивого переноса между сценами нет.
Снижение ошибки времени не компенсирует пропуски и ложные события.

Это повторно используемый development-датасет, а не новая внешняя проверка.
Дубликаты и связанные сцены разделены по группам; порог каждой модели выбран
на отдельном calibration-fold. Порог не подбирался по её outer-fold.
Рост точечных метрик не доказывает улучшение на новых камерах. Полные значения,
условные групповые bootstrap-интервалы и gates — в `semantic_metrics.json`.

## Что изменилось

- Вместо усреднения только общего вида кадра новый encoder сохраняет признаки
  четырёх пространственных областей; временная голова учитывает порядок восьми
  кадров, изменение состояния и движение между соседними кадрами.
- Обучение учитывает весь отрицательный видеоряд и размеченные моменты
  положительных записей. Остальные положительные окна не объявляются нормой.
- Признаки замороженного encoder кэшируются с проверками хеша видео, весов,
  preprocessing, размеров, конечности чисел и порядка времён. Искажённые кадры
  никогда не получают признаки исходного чистого кадра.
- Дополнительные зависимости необязательны для существующих моделей. Веса
  DINOv2 загружаются только из локальных safetensors с закреплёнными SHA-256.
- Для ONNX пространственное усреднение выражено через явные области; проверена
  эквивалентность прежнему adaptive pooling, в том числе на нечётной сетке.

20-epoch ablation проверен только на development-калибровке: binary macro F1
тот же 0.533, temporal recall хуже (0.667 против 1.000), MAE 4.00 против 2.52 s.
Оснований запускать его как ещё один выбранный OOF-кандидат не получено.

## Совместимость и скорость

89 ML-тестов пройдены. Финальная проверка без дополнительных DINO-пакетов:
88 passed, 1 optional test skipped.
На девяти полных held-out видео кэш и прямой расчёт дали одинаковые verdicts
и времена событий; максимальное отличие sigmoid-score — 0.00001398.

Экспериментальный bundle: `artifacts/ml/bundles/dino-spatial-mil-fold0`.
Он использует checkpoint fold 0 и предназначен для сравнения и интеграционных
проверок. Текущая поставка не перезаписана. PyTorch/ONNX проверены на шести
реальных окнах, batches 1 и 6: max logit error 0.00004387 при допуске 0.0001,
решения по порогу совпали. Manifest и checksums проверены.

Через существующий inference adapter `2f53ce1` проверены два полных видео,
69 окон, события и читаемые JPEG. Scores и timestamps совпали с ML runtime.
Повреждённый файл завершился `VideoOpenError`, без нормального verdict.
CPU-обработка заняла 36.14 и 30.39 s: ускорение приложения не достигнуто;
это существенный недостаток кандидата. Кэш признаков ускоряет эксперименты,
но не анализ нового видео в приложении. Live API не переключался.

## Типы событий

В `open/open_labels.xlsx` один лист `labels`, 42 строки, три столбца:
имя файла, таймстемп, нарушение / без нарушения. Типов событий в таблице нет.
После дедупликации остаётся 40 источников, 21 positive и 19 negative.

Подготовлен локальный черновик описаний наблюдаемых действий с кадрами и
полями для правила, типа, интервала и подтверждающего разметчика:
`artifacts/ml/semantic-20261018/review/index.html` и `event_review.json`.
Он не использован как истинная разметка. Многоклассовая модель и её точность
не заявляются. Для этого этапа нужны подтверждённые определения типов и
примеры, включая похожие разрешённые действия в отрицательных видео.

## Проверка устойчивости

Проверены девять полных видео outer-fold 0, с исходным порогом калибровки,
без его перенастройки на искажениях. Это частичная development-проверка,
не полный пятифолдовый stress-аудит и не проверка новой камеры.

| Условие | Macro F1 кандидата | Recall | Изменённых verdicts из 9 |
|---|---:|---:|---:|
| Исходное видео | 0.444 | 0.400 | 0 |
| Яркость ×0.65 | 0.444 | 0.400 | 0 |
| Яркость ×1.35, clipping | 0.444 | 0.400 | 0 |
| Смещение 5% вправо/вниз, отражение границ | 0.357 | 1.000 | 5 |
| JPEG quality 40 после resize | 0.649 | 0.800 | 2 |

Рост recall при смещении вызван тем, что все девять видео становятся
положительными: это потеря различения, а не достижение устойчивости.
JPEG на этой небольшой части улучшает метрики, но меняет решения; это также
не основание заявлять инвариантность к сжатию. Baseline на этих девяти видео
во всех пяти условиях выдаёт положительный результат для всех записей
(macro F1 0.357, recall 1.000); неизменность такого ответа не означает качество.

Следующий этап для реального повышения качества: подтверждённые интервалы
и типы, дополнительные пары похожих разрешённых/запрещённых действий, записи
с изменённым расположением камеры. Для отдельного эксперимента с аугментацией
смещения нужна повторная group-safe оценка; текущая уязвимость не объявлена
исправленной только по факту её обнаружения.
