# ML-диагностика перед демо

Дата: 2026-10-17. Ветка: `feature/ml-model`.
Код проверки и экспорта: `aba56d31030aa9830fe2770e4aa9d54d2879ef24`.
Статус: **development-only, quality gate не пройден**.

## 1. Причина повторяющейся десятой секунды

При настройках mock window=8, stride=2 и последовательности
`[0.1, 0.2, 0.8, 0.9, 0.3]` максимум первого цикла приходится на центр 10 s.
Выполнен именно `MockPredictor` из inference-коммита
`2f53ce18a91bcddae5135f2cac0a03aa36c7e7d4`: замена всех его кадров нулями
не меняет scores. Он возвращает готовый score; raw logit и sigmoid для mock
не существуют. Threshold ML-модели для исправления mock не изменялся.

## 2. Отличие настоящего ONNX

На заранее выбранном положительном calibration-ролике mock даёт пик 10 s,
ONNX — 19 s. У ONNX все 11 окон имеют разные входные тензоры; диапазон
logits составляет 0.245608. Обратный порядок подачи окон меняет logits на 0.
На четырёх положительных и четырёх отрицательных полных видео проверено
143 различных входа: ошибочного повторения изменившихся окон нет.
Это доказательство зависимости от содержимого, а не доказательство точности.

## 3. Найденные ML/data/pipeline проблемы

- Деление weighted loss на сумму весов текущего случайного мини-батча
  меняет целевое влияние источников. В предельном batch=1 веса полностью
  сокращаются. Контрольный тест показывает даже смену знака градиента.
- `events_complete=true` ранее не требовал подтверждённого reviewer.
- Разные точки у побайтных положительных дубликатов нельзя автоматически
  считать двумя подтверждёнными событиями. Семантический конфликт остаётся
  в очереди ручной проверки; утечки дубликатов между folds нет.
- Bundle проверял checksum, но не все заявленные правила postprocessing
  и связи threshold/metrics/compatibility после повторного подсчёта checksum.
- Синтетический неизвестный codec приводил к native access violation PyAV:
  `stream.codec_context` был `None`. Теперь ML отклоняет такой поток до decode
  контролируемой ошибкой. Регрессионный тест запускается в дочернем процессе,
  чтобы повторная нативная ошибка не могла оборвать весь pytest.
- Scores часто почти плоские, порог близок к наблюдаемым значениям;
  mean-pooling MobileNet не различает перестановку кадров внутри окна.
- В dataset отсутствуют подтверждённые интервалы; 14 из 21 положительного
  источника имеют medium/low confidence. Из восьми FN семь относятся к ним.

## 4. Внесённые изменения

- CLI `ml.diagnostics`: PTS, хеши входов, logits, sigmoid, smoothing,
  threshold, positive mask, события и полный локальный CSV/JSON timeline.
- Loss с нормировкой через средний вес dataset доступен отдельным явным
  config. Старый режим сохранён для воспроизведения baseline.
- Ограниченный hard-negative mining использует только отрицательные train
  источники, сохраняет начало/середину/конец и равный суммарный вес источника.
- Валидация полной разметки требует boolean, confirmed reviewer и интервалы.
- Усилена валидация bundle; новый scoring fingerprint связывает checkpoint,
  preprocessing/postprocessing pipeline и threshold.
- Добавлены positive F1, отдельные метрики без неоднозначного источника,
  групповые срезы, counts ошибок и воспроизводимые CLI экспериментов.
- Runtime может отдавать внутренние window scores, число supporting windows
  и их индексы. Публичный API и inference-код не изменены.
- После обнаружения decoder bug версия v3 оставлена неизменяемой, а поставка
  перевыпущена как v4 с новым fingerprint и повторной calibration/OOF оценкой.
  Исправление не меняет кадры или scores поддерживаемых видео.

## 5. Метрики до и после

Здесь 40 уникальных источников, 27 scenario groups, пять фиксированных outer
folds. В каждом: три train folds, отдельный calibration fold и outer evaluation.
Checkpoint берётся после заранее заданной эпохи. Каждый источник проверен
ровно один раз своей outer-моделью. SHA, source и scenario пересечений нет.
Dataset уже использовался в разработке: это повторная nested OOF оценка,
а не новый нетронутый внешний test. Final checkpoint на train не оценивался
как тестовый; полный прогон всех файлов использован только для runtime.

| Вариант | Precision | Recall | Positive F1 | Macro F1 | FP events/min | Event recall ±5 s | Peak MAE, s |
|---|---:|---:|---:|---:|---:|---:|---:|
| Baseline до изменений | 0.500 | 0.619 | 0.553 | 0.458 | 1.033 | 0.364 | 7.133 |
| Исправленная нормировка loss, 6 эпох | 0.483 | 0.667 | 0.560 | 0.413 | 1.191 | 0.409 | 5.624 |
| Поставляемый audited baseline | 0.500 | 0.619 | 0.553 | 0.458 | 1.033 | 0.364 | 7.133 |

Confusion matrix `[TN,FP; FN,TP]`: baseline `[6,13; 8,13]`, кандидат
`[4,15; 7,14]`. Кандидат отклонён: улучшение recall не компенсирует падение
macro F1 и рост FP. **Качество поставляемых весов не улучшилось.**

До outer-оценки проверены четыре development ablations на одних train и
calibration folds. Они дали macro F1=0.300, recall=1.000, FP/min=2.534,
event recall=0.667 на семи calibration-источниках. Это не test-метрики.

| Experiment | Единственное изменение относительно контроля | Time MAE, s | Решение |
|---|---|---:|---|
| weighted_objective | Нормировка loss относительно dataset вместо batch | 5.333 | Простейший исправленный контроль для OOF |
| weighted_objective_30 | 30 вместо 6 заранее заданных эпох | 5.333 | Выигрыша нет, отклонён |
| weighted_hard_negatives | Два трудных отрицательных окна с эпохи 4 | 5.333 | Выигрыша нет, отклонён |
| weighted_objective_8frames | 8 вместо 4 кадров | 6.000 | Выигрыша нет, отклонён |

Архитектура, window, stride, smoothing и разрешение при этих ablations
сохранены. После выбора простейшего контроля выполнена его OOF оценка;
эпоха не выбиралась по outer данным. Новые архитектуры не перебирались.

По folds и scenario cohorts: [diagnostic_metrics.json](diagnostic_metrics.json).
Индивидуальные scenario groups и подробные окна находятся только локально
в `artifacts/ml/diagnosis-v2/*/outer_*/details.json` и `summary.json`.

### Интерпретация временных метрик

FP/min — число событий **на отрицательных видео**, делённое на их минуты.
Event recall — однозначное сопоставление emitted peaks исходным точкам с
допуском 5 s. MAE включает дальние сопоставления, но не ненайденные события;
поэтому MAE обязательно читается вместе с event recall.

На подмножестве без неоднозначных двух точек baseline имеет event recall
0.400 и MAE 5.061 s; кандидат — 0.400 и 5.979 s. Видимое улучшение общего
MAE нельзя приписывать устойчивому улучшению локализации. Полной разметки
всех действий нет: unmatched peaks на положительных видео могут быть
неразмеченными событиями, поэтому они не доказывают ложное нарушение.

## 6. Temporal shift test

Нейтральный диагностический префикс — удержание первого кадра, а не
экспертно размеченная отрицательная сцена. Сохраняются реальные PTS;
промежуточные видео кодируются lossless FFV1 и остаются вне Git.

| Изменение | Пик до | Пик после | Ошибка сдвига | Совпавшие входы |
|---|---:|---:|---:|---:|
| Добавить 4 s | 19 s | 23 s | 0 s | 11/11 |
| Удалить 4 s | 19 s | 15 s | 0 s | 9/9 |

Разница logits соответствующих окон — 0. Событие сохраняется в обеих
копиях. Один успешный shift test не доказывает устойчивость всех сценариев.

## 8. Реальные ограничения и error analysis

Следующие группы частично пересекаются; counts нельзя складывать.

| Наблюдаемая группа baseline | Count | Возможная причина / решение | Проверка эффекта |
|---|---:|---|---|
| FP видео | 13 | Неспецифичные признаки сцены/действия; проверка разметки и train-only mining | Mining проверен, выигрыша нет |
| FN видео | 8 | Недостаточная разделимость классов | Исправленный loss уменьшил FN до 7, но увеличил FP |
| Ошибки с диапазоном raw scores <0.02 | 11 | Слабая чувствительность frozen ImageNet features | 30 эпох и 8 кадров не улучшили development-результат |
| Ошибки с отступом от threshold <0.01 | 8 | Нестабильная калибровка на малом fold | Калибровка отдельная; проблему разделимости не решила |
| FN на medium/low annotations | 7 | Сомнительная или сложная разметка; нужен reviewer | Семантическая проверка человеком не выполнена |
| FP events у начала/конца | 4 | Возможен фоновой или пограничный bias | PTS/tail корректны; причина содержимого не подтверждена |
| FN, raw peak проходит threshold, smoothed — нет | 1 | Smoothing поглощает короткий пик | Диагностировано; правило не менялось без нового согласованного сравнения |
| Positive с пропущенной/неточной точкой | 13 | Смешение scene recognition и temporal localization | Входы/shift проверены, качество остаётся низким |

Нельзя по одним scores посчитать перекрытия рук, похожее движение, человека
без действия, освещение, ракурс, статичную сцену или слишком короткое действие.
Для этих визуальных причин count **не установлен**, а не равен нулю.
Кадры не отправлялись во внешний AI API, экспертная разметка не выдумывалась.
Точное попадание sampled frames в краткое действие тоже нельзя подтвердить
по одной точке без интервала. Отдельного набора с другим углом нет.

Модель бинарная: `no_violation / possible_violation`. Допустимая формулировка:
«Модель обнаружила временной интервал с признаками возможного нарушения».
Score — ranking score. Тип действия, закон, полномочия человека и юридическое
решение модель не определяет. Следующий этап — подтверждённая taxonomy,
интервальная разметка, новые scenario/camera groups и внешняя проверка.

## 14. Inference-инженеру

Использовать canonical bundle adapter из `2f53ce1`, явный development opt-in,
RGB float32 NCTHW `[1,3,4,160,160]`, window=6, stride=2, tail=true,
ImageNet normalization, nearest PTS, sigmoid ровно один раз.
Smoothing `[.25,.5,.25]`, replicate edges, <3 окна без smoothing;
объединение соседних положительных центров в пределах stride; top-3 события.

Передаются start/end/peak_time/peak_score, `supporting_windows` (count),
`supporting_window_indices` и внутренний список window scores. Для JPEG
нужно выбирать информативные разные кадры внутри события. Три близких JPEG
и округление 9/10/10 остаются отдельной задачей inference/frontend.

**Найден блокер:** `cv2.imwrite` в текущем evidence.py не сохраняет JPEG
под Windows в каталоге с кириллицей. Скоринг уже прошёл, но полный pipeline
завершается `EvidenceExtractionError`, что корректно лучше ложного verdict.
Временный обход — ASCII evidence root. Исправление владельцем: кодировать
через `cv2.imencode`, записывать bytes через `Path.write_bytes`, добавить
Unicode-output test. Здесь чужой код не менялся.

Ещё один фактический результат: на неизвестном codec текущий inference reader
бросает `AttributeError` при чтении metadata. Verdict не выдан. Нужен guard
отсутствующего codec_context до width/decode и структурированный
`UnsupportedVideoError`; ML sampler уже исправлен и покрыт отдельным тестом.

Подключить `load_bundle_contract(..., allow_development_model=True)` →
`OnnxPredictor` → `analyze_video` в composition root API, проверить модельный
SHA и логировать фактические predictor class/model_version при старте.

готового подтверждённого переключателя окружения для нового ONNX API там нет.
Одна замена `FORTEBANK_MODEL_PATH` не является проверенной интеграцией ONNX.

Успешный `possible_violation` отображается в публичное `violation` только
адаптером API; любая техническая ошибка — `failed`, без отрицательного verdict.
Использовать ASCII evidence root до исправления владельцем. Затем проверить
API positive/negative/corrupt, повторную загрузку, frontend и общий лимит 300 s.
Полный API end-to-end и live backend в этой ML-задаче не перезапускались.
